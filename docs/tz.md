Развитие лендинга снэпбилд 
───────────── 
Контекст задачи 
У снэпбилд есть действующий продуктовый лендинг, рассказывающий о возможностях платформы 
для создания сайтов, изображений, видео, баннеров и презентаций в рамках дизайн-системы 
компании. 
Вам необходимо изучить существующий сайт и продолжить его дизайн, добавив новые 
содержательные секции. 
Что нужно реализовать 
1. Добавить пять новых секций 
Разработайте пять новых секций для лендинга снэпбилд. Тематику и содержание можно выбрать 
самостоятельно. 
Это примеры, а не обязательный набор. Допускаются другие секции, если они подходят продукту и 
логично продолжают текущую страницу. 
Параметр Значение
Расчётное время 4–6 часов (с использованием AI-инструментов)
Стек На ваш выбор
Исходный сайт https://snapbuild.ru/
Сдача GitHub-репозиторий + опубликованная версия на 
GitHub Pages
Ключевая задача: новые блоки должны восприниматься как естественная часть существующего 
лендинга, а не как элементы из другого шаблона или отдельного проекта.
Возможный блок Примеры содержания
Тарифы Варианты подключения, набор возможностей, CTA
Отзывы Цитаты клиентов, должность, компания, результат
Кейсы использования Сценарии для маркетинга, дизайна, продаж или 
продукта
Форма обратной связи Поля заявки, валидация, сообщение об успешной 
отправке
Другие варианты Интеграции, этапы внедрения, метрики, аудитории, 
примеры материалов

•Секции должны отличаться друг от друга по структуре и назначению. 
•Контент должен соответствовать продукту снэпбилд. 
•Каждая секция должна быть полноценной частью страницы, а не одной небольшой карточкой 
или строкой текста. 
•Новые элементы должны использовать визуальные паттерны исходного сайта. 
•Не следует использовать несвязанный UI-kit или копировать готовые секции с других сайтов. 
•Тексты не должны состоять из Lorem Ipsum. 
2. Сохранить стилистику исходного сайта 
Это ключевая часть задания. Новые секции должны сохранять стилистику и визуальный язык 
текущего лендинга и восприниматься как его естественное продолжение. 
3. Собрать единый лендинг 
В итоговой версии должны быть представлены существующие блоки лендинга снэпбилд и пять 
разработанных вами секций. Все элементы должны быть собраны в одну последовательную 
страницу. 
•Новые секции следует расположить там, где они логично дополняют существующий контент. 
•Результат не должен выглядеть как отдельная демонстрационная страница только с пятью 
новыми компонентами. 
•Будет плюсом, если вы самостоятельно воспроизведёте текущие секции сайта и вставите 
новые блоки непосредственно между ними. 
4. Адаптивная версия 
Страница должна корректно отображаться как минимум на следующих ширинах: 
•контент не выходит за границы экрана 
•текст остаётся читаемым 
•карточки и колонки корректно перестраиваются 
•кнопки и интерактивные элементы остаются доступными 
•отсутствует горизонтальный скролл 
5. Интерактивные элементы 
Если в новых секциях используются интерактивные элементы, они должны работать. Это могут 
быть переключатель тарифов, FAQ, вкладки, слайдер отзывов, форма, модальное окно или другие 
элементы. 
Для формы не требуется реальная серверная отправка. Достаточно базовой валидации, понятных 
ошибок и состояния успешной отправки. 
Мы не ожидаем точного восстановления внутренней дизайн-системы. Важно показать, что вы 
умеете анализировать существующий интерфейс и последовательно продолжать его 
визуальный язык.

Дополнительная часть 
Полное копирование существующего лендинга не является обязательным требованием, но 
оценивается как дополнительное преимущество. 
Технические требования 
Стек можно выбрать самостоятельно: HTML/CSS/JavaScript, React, Next.js со статическим 
экспортом или другой современный frontend-стек. 
•проект запускается локально по инструкции из README 
•проект собирается без ошибок 
•проект корректно работает после публикации на GitHub Pages 
•структура файлов и компонентов понятна 
•в консоли нет критических ошибок 
•для запуска не требуются закрытые ключи или платные сервисы 
Что должно быть в README 
1.Краткое описание выполненной работы. 
2.Ссылка на опубликованную страницу. 
3.Инструкция по локальному запуску. 
4.Использованный стек. 
5.Перечень пяти добавленных секций. 
6.Как анализировалась стилистика исходного сайта. 
7.Какие части исходной страницы удалось воспроизвести. 
8.Что не удалось реализовать и почему. 
9.Что бы вы улучшили при наличии дополнительного времени. 
10.Какие AI-инструменты использовались и для каких задач. 
Формат сдачи 
•Публичный GitHub-репозиторий. 
•Рабочая ссылка на опубликованный проект в формате username.github.io/project-name. 
•README.md с инструкцией запуска и описанием принятых решений. 
Вариант Что ожидается
Базовый Передать общую структуру и стилистику текущего 
сайта, затем добавить пять новых секций.
Расширенный
Максимально точно воспроизвести существующие 
секции: шапку, первый экран, продуктовые блоки, 
преимущества, безопасность, дорожную карту, FAQ, 
финальный CTA и подвал; после этого встроить пять 
новых секций.
Проект должен быть опубликован на GitHub Pages. Перед отправкой проверьте, что ссылка 
открывается без авторизации и страница корректно загружается.
