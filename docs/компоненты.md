# Снэпбилд — визуальный язык и компонентная база

Разбор стилистики https://snapbuild.ru/ для ТЗ «добавить 5 новых секций так, чтобы они
воспринимались как естественная часть лендинга».

Источник данных: живой HTML страницы + 4 таблицы стилей
(`assets/css/38d310b04484773c.css`, `hero-motion.css`, `overrides.css`, `large-screens.css`).
Все значения ниже — фактические, вытащены из CSS, а не восстановлены на глаз.

---

## 1. Что за продукт и какой у него тон

**Снэпбилд** — платформа генерации маркетинговых материалов (сайты, изображения, видео,
баннеры, презентации) строго внутри дизайн-системы клиента. Ключевое обещание:
«AI не может нарушить бренд».

Тон текстов:
- Заголовки — короткое утверждение-обещание, без восклицаний:
  «Одна платформа — весь маркетинг», «Безопасность без компромиссов»,
  «Каждый день — новый релиз».
- Подзаголовок — одно предложение, раскрывающее выгоду, часто через тире:
  «Ваши компоненты, цвета и шрифты — единственный источник стиля».
- Активно используется **длинное тире** и конструкция «X — Y».
- Цифры и конкретика: «5 минут», «100% точность», «до 4K», «на 78% точнее», «152-ФЗ».
- Бренд пишется строчными: **снэпбилд** / «Снэпбилд» в начале предложения. Не «SnapBuild».
- Никакого капса в заголовках, никаких «!», никакого «Мы — команда профессионалов».

## 2. Архитектура страницы (порядок секций)

| # | `id` | Классы | Назначение |
|---|------|--------|-----------|
| 1 | `header` | `dds-header dds-main` | Фиксированная шапка, «пилюля»-навигация |
| 2 | `hero` | `dds-app-preview` | Первый экран + большой медиа-кард |
| 3 | `logos` | `dds-logos dds-marquee` | Бегущая строка логотипов клиентов |
| 4 | `process` | `dds-steps` | 3 карточки-преимущества |
| 5 | `use-cases` | `dds-use-cases dds-tabs` | 5 вкладок × список пунктов с прогресс-баром |
| 6 | `compare` | `dds-compare dds-benefit` | Сравнительная таблица с конкурентами |
| 7 | `features` | `dds-why-safe` | Безопасность: тёмная карточка + 3 пункта |
| 8 | `roadmap` | `dds-rmap` | Горизонтальный таймлайн, 14 пунктов |
| 9 | `faq` | `dds-faq dds-accordion` | Аккордеон в 2 колонки, 8 вопросов |
| 10 | `cta` | `dds-cta dds-launch` | Финальный призыв на градиентном фоне |
| 11 | `footer` | `dds-footer` | Подвал в 3 колонки + cookie-баннер |

**Куда логично встроить новые секции:**

- **Кейсы использования** → после `use-cases` (6), развивает тему сценариев.
- **Тарифы** → после `compare` (7), сразу за аргументом «почему мы».
- **Отзывы** → после `features` (8), социальное доказательство перед роадмапом.
- **Интеграции / этапы внедрения / метрики** → между `roadmap` и `faq`.
- **Форма обратной связи** → перед `cta` или вместо него как расширенный CTA.

Не ставить новое между `hero` и `logos` — там жёсткая связка первого экрана.

## 3. Фундамент: всё измеряется в `vw`, а не в `px`

Это **главная особенность вёрстки**. Почти каждый размер — шрифт, паддинг, gap, радиус —
записан как доля от ширины макета:

```css
font-size: calc(52 / 14.4 * 1vw);   /* 52px на макете 1440px */
padding:   calc(96 / 14.4 * 1vw) calc(40 / 14.4 * 1vw);
gap:       calc(40 / 14.4 * 1vw);
```

Делитель = ширина макета / 100:

| Брейкпоинт | Ширина макета | Делитель | Медиазапрос |
|---|---|---|---|
| Desktop | 1440 px | **14.4** | по умолчанию |
| Tablet | 810 px | **8.1** | `@media (min-width: 768px) and (max-width: 1023px)` |
| Mobile | 375 px | **3.75** | `@media (max-width: 767px)` |

Поведение на больших экранах (`large-screens.css`):
- **1440–2560 px** — масштаб продолжает расти линейно, px-значения тоже конвертированы в vw.
- **≥ 2560 px** — макет заморожен на `1.7778×` от исходного, `body { max-width: 2560px; margin-inline: auto }`,
  поля по краям закрашены цветом страницы.

> **Если писать новые секции в обычных `px` — они «поплывут» относительно соседних
> и это будет заметно сразу.** Новые блоки обязаны использовать ту же формулу.

Исключения, где авторы оставили честные `px`: базовые UI-примитивы `.dds-btn`, `.dds-tag`,
`.dds-tabs` (12–16 px шрифт, радиусы 12/24/50 px) и cookie-баннер.

## 4. Цветовая гамма

### 4.1 Корневые токены (`:root`, светлая тема)

```css
:root{
  --background-primary:  #F2F2F4;   /* фон страницы, основной */
  --background-secondary:#FFFFFF;
  --foreground-primary:  #FFFFFF;   /* фон карточек */
  --foreground-secondary:#FAFAFA;   /* фон элементов аккордеона */
  --foreground-tertiary: #F5F5F7;   /* неактивные табы, плитки */
  --foreground-contrast: #FFFFFF;
  --text-primary:  #000000;
  --text-secondary:#5A5B62;         /* весь вторичный текст */
  --text-tertiary: rgba(0,0,0,0.6); /* подзаголовки в hero/benefit */
  --text-contrast: #FFFFFF;
  --icon-primary:  #000000;
  --icon-contrast: #FFFFFF;
  --stroke-primary:  rgba(0,0,0,0.05);
  --stroke-secondary:rgba(0,0,0,0.4);
  --stroke-tertiary: rgba(0,0,0,0.1);
  --surface-glass-strong: rgba(0,0,0,0.03);
  --divider-color: rgba(0,0,0,0.08);
  --color-background: #F2F2F4;
}
```

**Важная ловушка:** шаблоны `dds-*` написаны «тёмными по умолчанию» — в них полно
фолбэков вида `var(--color-background, #000)`, `var(--text-primary, #fff)`.
Живая страница светлая только потому, что `:root` переопределяет токены.
При копировании кусков CSS фолбэки надо привести к светлым значениям, иначе секция
почернеет там, где токен не дошёл.

### 4.2 Нейтральная шкала

```
--color-neutral-100 #FFFFFF   --color-neutral-200 #F2F2F4   --color-neutral-300 #E5E5E7
```
Плюс серые из hover-состояний: `#F5F5F7`, `#EBEBEE`, `#CDCCCD`.

### 4.3 Тёмные поверхности (точечно, на светлом фоне)

```
#141318   карточка «Безопасность» (#features .dds-why-safe-card)
#141414   кнопка --secondary, hover #0A0A0A
#111111   тег --no в таблице сравнения
#000000   активный таб в use-cases
```

### 4.4 Акцент — фирменный градиент «закат»

Единственный источник цвета на странице. Одна и та же триада во всех вариантах:

```css
/* Основной, для текста и заливок */
linear-gradient(90deg, #ff6d3c, #ff6ba7 46%, #bb6dff);

/* Роадмап, пройденные точки */
linear-gradient(91.76deg, #ff6d3d 1.5%, #ff6ca7 56.4%, #bb6dff 103.9%);

/* Пастельный — рамки активных карточек, прогресс-бары */
linear-gradient(135deg, #ffcdb3 0%, #ffa4b6 40%, #ffb2e9 70%, #d4d6ff 100%);

/* Фон финального CTA */
linear-gradient(157deg, #fff 17.71%, #ffd1b9 43.16%, #ffabbc 58.2%,
                        #ffb8eb 73.32%, #d7d9ff 90.8%, #fff 103.16%);

/* Свечение под плиткой-иконкой */
radial-gradient(circle at 50% 100%, rgba(255,109,61,.35),
                rgba(255,108,167,.2) 45%, rgba(187,109,255,.08) 72%, transparent 100%);
```

Опорные хексы: **`#ff6d3c` оранжевый → `#ff6ba7` розовый → `#bb6dff` фиолетовый.**

Три приёма применения градиента (используй их, а не сплошную заливку):
1. **Градиентный текст** — кнопка «Начать сейчас» в шапке:
   `background-image: <градиент>; -webkit-background-clip: text; color: transparent;`
2. **Градиентная рамка** — активная карточка вкладок:
   `background: linear-gradient(#fff,#fff) padding-box, <градиент> border-box; border: 2px solid transparent;`
3. **Градиентная заливка** — прогресс-бар, точки роадмапа, бейдж на переключателе.

> Сплошного «брендового синего» на сайте нет. `--color-primary-*` (#3758f9 и др.)
> лежат в CSS как остаток фреймворка и **на странице не используются** — не брать.

фолбэк `"Satoshi Variable"`). Файлы шрифта на сайт не подключены — ни `@font-face`,

### 5.2 Правила, которые надо повторить

- **H2 любой новой секции = 52 / 52 / 32 px** с отрицательным трекингом. Это опознавательный
  знак страницы: заголовок крупный, плотный, всегда чёрный.
- Отрицательный letter-spacing применяется только к крупному тексту (≥ 16 px заголовочного
  типа), у body-текста он всегда `0`.
- Line-height записывается либо дробью от кегля (`calc(64 / 52)`), либо десятичным
  (`1.4286` = 20/14, `1.3334` = 32/24, `1.2308` = 64/52). Это те же значения, просто две записи.
- Пара «заголовок + подзаголовок» разделена `gap: calc(8 / 14.4 * 1vw)` — очень плотно.
- Вторичный текст **всегда** `#5A5B62`. Не `#666`, не `rgba(0,0,0,.6)` (последний — только
  в hero и benefit).

## 6. Форма: радиусы, тени, границы

**Радиусы** (нет единой шкалы — есть набор фактических значений):

```
9999px / 999px / 50px  пилюли: навигация, табы, кнопка CTA, бейджи
32→24→15 px            hero-медиа (calc от vw)
36 / 32 px             плитка-иконка в «Безопасности»
24 px                  --card-radius, крупные карточки, .dds-btn--l
20 px                  карточка вкладки, элемент аккордеона, тёмная карточка
16 px                  плитка иконки, группа кнопок
12 px                  .dds-btn базовый; на мобиле все кнопки схлопываются в 12 px
```

Токены из фреймворка: `--radius-sm .25rem`, `--radius-md .5rem`, `--radius-lg .75rem`,
`--radius-xl 1rem`, `--radius-2xl 1.5rem`, `--radius-full 9999px`.

**Тени** — их почти нет, дизайн плоский:

```css
0 4px 16px rgba(0,0,0,0.04);   /* пилюля в hero */
0 16px 40px rgba(0,0,0,0.12);  /* всплывающие слои */
0 1px 2px #0000000d;           /* мельчайший подъём */
--btn-glass                    /* «стеклянная» тень primary/secondary кнопок */
```

**Границы** — тонкие и почти прозрачные: `1px solid rgba(0,0,0,0.08)`,
`--divider-color rgba(0,0,0,0.08)`, `--stroke-tertiary rgba(0,0,0,0.1)`.
Разделитель в use-cases: `--dds-use-case-rule: max(1px, calc(1 / 14.4 * 1vw))`.

### 7.4 Аккордеон (FAQ)

```css
.dds-accordion{ padding: calc(96/14.4*1vw) calc(40/14.4*1vw); gap: calc(64/14.4*1vw) }
.dds-accordion-item{ background: var(--foreground-secondary,#FAFAFA);
                     border-radius:20px; padding: calc(20/14.4*1vw) }
.dds-accordion-head{ gap: calc(20/14.4*1vw) }
```
Раскрытие сделано через `grid-template-rows: 0fr → 1fr`:
```css
transition: grid-template-rows .2s cubic-bezier(.16,1,.3,1),
            margin-top       .2s cubic-bezier(.16,1,.3,1);
/* иконка */ transform .2s cubic-bezier(.16,1,.3,1);
/* ответ  */ opacity   .2s cubic-bezier(.16,1,.3,1);
```
Состояние — `<input type="checkbox" class="dds-accordion-state">` + `<label>`. Снова без JS.
Раскладка: 2 колонки (`.dds-accordion-col`), 8 элементов.
Паддинги: `96/40 → 60/20 → 48/16`, gap `64 → 40 → 40`.

### 7.7 Переключатель-сегмент (пригодится для тарифов «месяц/год»)

## 8. Motion

```css
/* базовые длительности */
--dds-dur-fast: .2s;
--dds-btn-dur:  .4s;   --dds-btn-ease: cubic-bezier(.4,0,.2,1);
--dds-motion-accordion-close-duration: .2s;
--dds-motion-accordion-easing:  cubic-bezier(.16,1,.3,1);
--dds-motion-control-duration:  .267s;
--dds-motion-control-easing:    cubic-bezier(.55,0,.1,1);
--ease-in-out: cubic-bezier(.4,0,.2,1);
```

**Появление при скролле** — два класса, один паттерн:

```css
.dds-reveal{ opacity:0; transform: translateY(32px);
  transition: opacity .9s cubic-bezier(.16,1,.3,1), transform .9s cubic-bezier(.16,1,.3,1);
  will-change: opacity, transform }
.dds-reveal.is-visible{ opacity:1; transform:none }

.reveal{ opacity:0; transform: translateY(1.5rem);
         transition: opacity .5s ease, transform .5s ease }
.reveal.is-visible,
.reveal.reveal--visible{ opacity:1; transform:none }
.reveal--delay-1{ transition-delay:.1s }
.reveal--delay-2{ transition-delay:.2s }
.reveal--delay-3{ transition-delay:.3s }
```

Класс переключается `IntersectionObserver`'ом. Ступенчатая задержка `--delay-1/2/3` даёт
каскад по карточкам — обязательно повторить в новых секциях.

**Обязательно:** оба класса обёрнуты в `@media (prefers-reduced-motion: reduce)`,
где анимация полностью снимается (`opacity:1; transform:none; transition:none`).
На странице 7 таких блоков — доступность соблюдена, новые секции должны её держать.

**Keyframes:** `dds-marquee-scroll` (бегущая строка логотипов, пауза пока секция
не видна), `cta-blob-a` / `cta-blob-b` (плавающие пятна в финальном CTA),
`cta-shine`, `dds-btn-text-shine`, `dds-btn-text-sweep`.

Другие переходы: `color .3s ease`, `grid-template-rows .5s cubic-bezier(.22,1,.36,1)`.
Hover-эффекты спрятаны в `@media (hover: hover)` — 19 таких блоков.

## 9. Соглашения разметки

```html
<section class="<смысл> dds-<шаблон>"
         data-cms-section="<смысл>.<шаблон>"
         id="<смысл>">
  <div class="dds-<шаблон>-header">
    <h2 class="dds-<шаблон>-title">…</h2>
    <p  class="dds-<шаблон>-subtitle">…</p>
  </div>
  …
</section>
```

- Классы — `dds-<блок>-<элемент>[--модификатор]`, плоский BEM без вложенности.
- У секции есть и семантический класс (`faq`, `compare`), и класс шаблона (`dds-accordion`,
  `dds-benefit`). Тонкая настройка делается через `#id .dds-*` — так авторы кастомизируют
  общий шаблон под конкретную секцию (например, `#features .dds-why-safe-card{background:#141318}`).
  **Тот же приём стоит применить и к новым секциям**: взять существующий шаблон и
  дописать `#pricing .dds-…`.
- Интерактив помечается атрибутами `data-cms-interaction="disclosure"`,
  `data-cms-interaction-control`.
- Интерактив без JS: `input[type=radio|checkbox]` + `label` + `:checked ~`.
- Язык страницы `ru`, `theme-color` = `#f2f2f4`.

## 11. Вертикальный ритм секций

| Секция | Desktop padding | Tablet | Mobile | gap |
|---|---|---|---|---|
| `dds-steps` | `96 / 40` | `60 / 20` | `48 / 16` | 40 → 40 → 32 |
| `dds-tabs` | `96 / 40` | `60 / 20` | `48 / 16` | — |
| `dds-accordion` | `96 / 40` | `60 / 20` | `48 / 16` | 64 → 40 → 40 |
| `dds-benefit` | `32 / 40` | `32 / 20` | `32 / 0` | 40 → 40 → 32 |
| `dds-why-safe` | `32 / 40` | `32 / 20` | `32 / 20` | 32 → 32 → 32 |
| `dds-rmap` | `32 / 0` | `32 / 0` | `32 / 0` | 56 → 56 → 32 |
| `dds-footer` | `32 / 40 / 40` | `32 / 20 / 32` | `24 / 16 / 24` | 40 → 40 → 32 |

Все значения — в `calc(N / делитель * 1vw)`.

**Итого два ритма:**
- «Крупный» — `96 / 40` (`60/20`, `48/16`): смысловой блок с большим заголовком.
- «Плотный» — `32 / 40`: секция примыкает к соседней, работает как её продолжение.

Боковой отступ страницы: **40 px** (desktop) / **20 px** (tablet) / **16 px** (mobile).
Новая секция обязана попасть в эту вертикаль, иначе её края «уедут» от соседних.

## 12. Чеклист «свой / чужой»

Перед сдачей секции проверить:

- [ ] Все размеры записаны как `calc(N / 14.4 * 1vw)`, а не в `px` / `rem`.
- [ ] Есть все три брейкпоинта: default, `768–1023`, `≤767`.
- [ ] Боковые паддинги — 40 / 20 / 16 px в vw-записи.
- [ ] H2 = 52 / 52 / 32 px, вес 500–600, отрицательный letter-spacing.
- [ ] Подзаголовок = 16 / 16 / 14 px, цвет `#5A5B62`, gap до заголовка 8 px.
      Вес в исходнике плавает (400 у process и faq, 500 у roadmap, compare, cta);
      в реплике он сведён к одному значению — 400.
- [ ] Фон секции — `#F2F2F4`, карточки — `#FFFFFF`. Не белая секция на белом.
- [ ] Цвет — **только** через градиент `#ff6d3c → #ff6ba7 → #bb6dff` (текст, рамка, заливка).
      Никаких синих, зелёных, «success/danger» цветов.
- [ ] Радиус: 20–24 px у карточек, 999px у пилюль, 12 px у базовых кнопок.
- [ ] Теней либо нет, либо `0 4px 16px rgba(0,0,0,.04)`.
- [ ] Есть `.dds-reveal` / `.reveal` + `--delay-1/2/3` для каскада.
- [ ] Есть блок `@media (prefers-reduced-motion: reduce)`.
- [ ] Hover-эффекты — внутри `@media (hover: hover)`.
- [ ] Классы названы `dds-<блок>-<элемент>`, у секции есть `id`.
- [ ] Кнопки взяты из `.dds-btn` / `.dds-btn--l`, а не написаны заново.
- [ ] Bold 700 не использован нигде.
- [ ] Скопированные фолбэки `var(--x, #000)` / `var(--x, #fff)` приведены к светлой теме.
- [ ] Нет горизонтального скролла на 1280 / 768 / 375.

## 13. Заготовки под пять новых секций

Все пять переиспользуют существующие шаблоны — это и есть способ «встроиться».

| Секция | Где ставить | Взять за основу | Интерактив |
|---|---|---|---|
| **Тарифы** | после `#compare` | `dds-tabs-card` (карточка) + `dds-btn-group` (переключатель) | сегмент «Месяц / Год», выделенный тариф — градиентной рамкой |
| **Кейсы использования** | после `#use-cases` | `dds-steps` (3 карточки) | вкладки по индустрии на `input:radio` |
| **Отзывы** | после `#features` | `dds-steps-card` + `.dds-app-preview-pill` для должности | слайдер со scroll-snap, точки — как `dds-rmap-dot` |
| **Этапы внедрения / интеграции** | между `#roadmap` и `#faq` | `dds-rmap` (таймлайн с точками) | точки пройденных этапов заливаются градиентом |
| **Форма заявки** | перед `#cta` | токены `--input-*` / `--textarea-*` уже есть в CSS | валидация, ошибки, состояние успеха |

Поля формы уже описаны токенами в основном CSS — их достаточно применить:
```
--input-border-color:       var(--color-neutral-300)   /* #E5E5E7 */
--input-border-color-focus: var(--color-primary-400)   /* заменить на #ff6ba7 */
--input-radius:             var(--radius-md)           /* .5rem — лучше поднять до 12px */
--textarea-min-height:      6rem
--textarea-placeholder-color: var(--color-neutral-500)
```
Фокус на полях лучше подсветить фирменным розовым `#ff6ba7`, а не остаточным
синим `--color-primary-400` — синий на странице не встречается.

## Краткая формула стиля

> Светло-серый холст `#F2F2F4` · белые карточки с радиусом 20–24 px · чёрная плотная
> типографика 52/16 с отрицательным трекингом · вторичный текст `#5A5B62` ·
> единственный цвет — градиент закатных оттенков `#ff6d3c → #ff6ba7 → #bb6dff`,
> и тот применяется точечно: текстом кнопки, рамкой активной карточки, заливкой прогресса ·
> плоско, без теней · всё измерено в `vw` от макета 1440 · появление снизу вверх при скролле ·
> интерактив на чистом CSS.
