# Снэпбилд — развитие лендинга

Тестовое задание Fullstack Developer: воспроизведение лендинга [snapbuild.ru](https://snapbuild.ru/)
и новые секции, встроенные внутрь страницы.

## 1. Что сделано

- **Одна страница** — 12 секций плюс шапка и подвал: восемь
  с оригинала, четыре новые
- **Новые блоки встроены внутрь** — стоят между исходными по смыслу, а не
  отдельной демонстрацией в конце
- **Стилистика разобрана по коду сайта**, а не восстановлена на глаз — результат
  в [`docs/компоненты.md`](docs/компоненты.md)

## 2. Опубликованная версия

https://samandr77.github.io/snapbuild-test-task/


## 3. Локальный запуск

Нужен Node.js 18+. 

```bash
make dev        # установка зависимостей + дев-сервер
```

Остальные команды:

| Команда | Что делает |
|---|---|
| `make install` | Установить зависимости |
| `make dev` | Дев-сервер — http://localhost:5173/snapbuild-test-task/ |
| `make build` | Сборка в `dist/` |
| `make preview` | Просмотр сборки — http://localhost:4173/snapbuild-test-task/ |
| `make test` | Браузерные тесты интерфейса (нужен установленный Chrome) |
| `make clean` | Удалить `dist` и `node_modules` |


## 4. Стек

- **React 18 + TypeScript** — секция = компонент, состояние интерактива локальное
- **Vite 6** — дев-сервер и статическая сборка
- **CSS без фреймворков** — своя дизайн-система на кастомных свойствах.
  Готовый UI-kit принёс бы чужие радиусы, тени и типографику — это противоречит задаче
- **Тесты** — `node --test` + Chrome по CDP, без внешних зависимостей

```
src/
├── assets/         логотипы, кадры секций, шрифт
├── components/     переиспользуемая база
├── sections/       секции страницы
├── data.ts         весь текст
├── styles.css      дизайн-система и стили
└── App.tsx         порядок секций
```

форма и отзывы — сразу за FAQ, когда возражения уже сняты.

## 6. Как анализировалась стилистика

Разбор шёл по коду сайта, а не по скриншотам: выгружены HTML и таблицы стилей
snapbuild.ru, сверка — по `getComputedStyle`, снятому браузером с живой страницы.

| Что | Что нашлось в оригинале | Как сделано здесь |
|---|---|---|
| Масштаб | Каждый размер записан как `calc(N / 14.4 * 1vw)` | Одна переменная `--u`, через неё все отступы и радиусы |
| Цвет | Холст `#F2F2F4`, карточки белые, вторичный текст `#5A5B62` | Токены заданы явно |
| Акцент | Единственный градиент `#ff6d3c → #ff6ba7 → #bb6dff` | Три приёма исходника: заливка текста, градиентная рамка, заливка прогресса |
| Типографика | Веса 400–600, bold 700 не встречается; заголовок секции 52 / 39 / 32 px | Тот же диапазон весов, шкала на непрерывном `clamp()` |
| Анимации | Блик по градиентному тексту, тёмная полоса по светлому, `scale: 0.975` на нажатие | Перенесены как есть, снимаются в `prefers-reduced-motion` |
| Ловушка | Шаблоны `dds-*` написаны «тёмными по умолчанию», светлыми их делает только `:root` | Все токены заданы явно, без опоры на фолбэки |

Расхождения, невидимые на глаз: фон страницы `#F5F5F6`, а не `#F2F2F4`; заголовки
весом 500, а не 600; отступы секций 32 px сверху и 96–128 px снизу.

Полный разбор — [`docs/компоненты.md`](docs/компоненты.md).

## 7. Что воспроизведено

Шапка с навигацией-«пилюлей» и бургер-меню, первый экран, бегущая строка логотипов,
«Одна платформа — весь маркетинг», продуктовый блок с форматами, сравнительная
таблица, дорожная карта, FAQ, финальный CTA, подвал.

Плюс механики оригинала: fluid-vw масштабирование, появление блоков при скролле,
`prefers-reduced-motion`, закреплённый первый столбец таблицы на узких экранах.

## 8. Что не реализовано и почему

Хотел бы ещё поработать над очерёдностью блоков и выстраиванием воронки —
чтобы страница последовательно вела пользователя к целевому действию,
а не просто перечисляла возможности.

- **Пятая новая секция.** ТЗ просит пять, сделано четыре: время ушло на точность
  воспроизведения исходных секций.
- **Блок безопасности** из расширенного варианта не воспроизведён по той же причине.
- **Логотип** нарисован приблизительно — оригинального файла нет в открытом доступе.
- **Отправка формы** на сервер не делалась: по условиям задачи не требуется,
  форма доходит до состояния успеха на клиенте.





## 9. Что улучшил бы при наличии времени

- Анимации: сейчас они рабочие, но простые — хочется более плавных и продуманных переходов
- Оформление: больше премиальности и уклона в целевую аудиторию продукта
- Анализ рынка: посмотреть на конкурентов и понять, какое решение будет выгоднее с точки зрения продаж
- Тесты на клавиатуру и скринридер: разметка и `aria-*` расставлены, но проверка была инструментальной

## Публикация на GitHub Pages

1. Создать публичный репозиторий с именем `snapbuild-test-task`.
   Другое имя — поправить `base` в [`vite.config.ts`](vite.config.ts).
2. Запушить код в ветку `main`.
3. Settings → Pages → Source → **GitHub Actions**.

Дальше [`deploy.yml`](.github/workflows/deploy.yml) сам прогонит тесты, соберёт и опубликует.
